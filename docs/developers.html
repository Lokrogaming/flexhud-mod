Eigene Packs bauen

Ein FlexHUD-Pack ist eine .zip mit Widgets, Stil und optionaler .flexconfig für Meta + Custom-Buttons. Hier steht alles: Pack-Aufbau, Referenzen, Marketplace-Eintrag, Mod bauen und Integration (Bridge, i18n, Konflikte, Updates).

1. Pack-Aufbau

mein-pack/
  pack.json            # PFLICHT im Zip-Root (widgets[] werden importiert)
  mein-pack.flexconfig # optional: Meta + Custom-Buttons (Name frei, *.flexconfig)
  README.md            # optional
  assets/...           # optional (Icons: reserviert, Auswertung später)

Zip so packen, dass pack.json im Root liegt – sonst importiert FlexHUD nichts. Als GitHub-Release-Asset hochladen (stabiler Direkt-Link).

pack.json (Beispiel)

{
  "packId": "mein-pack",
  "packName": "Mein Pack",
  "packVersion": "1.0.0",
  "requiresModId": "meine-mod",
  "requiresJarHints": ["meine-mod"],
  "widgets": [
    {
      "type": "TEXT", "template": "Hallo Welt",
      "x": 0.5, "y": 0.2, "enabled": true,
      "style": {
        "gradient": ["00FFCC", "AA55FF"], "animation": "SCROLL_L",
        "cycleMs": 3500, "bold": true, "italic": false,
        "shadow": true, "background": false, "backgroundOpacity": 120,
        "scale": 1.0, "hideText": false, "staticColor": "FFFFFF"
      }
    }
  ]
}

Widget-Typen: TIMER, STEPCOUNT, CLOCK, TEXT, FPS. Timer-Vorlagen verstehen {value} plus {d} {h} {m} {s} {ms}. IDs werden beim Import neu vergeben, Positionen/Styles bleiben.

2. .flexconfig-Referenz

Optionale Datei im Pack-Root. Meta erscheint im Marketplace, configMenu (muss explizit deklariert sein!) erscheint im Overview-Menü und wirkt auf alle Pack-Widgets, widgetButtons erscheinen als ★-Buttons im Stil-Menü und wirken aufs gewählte Widget.

Meta-Felder

packIdjaMuss zur Pack-ID passen
author, websiteneinAnzeige im Marketplace (bei installierten Packs)
created, updatedneinDatum, „Stand …“-Anzeige (Format frei, z. B. 2026-10-09)

Button-Aktionen

action weitere FelderWirkung
toggleStylefield: bold, italic, shadow, background, hideTextFlag umschalten
setStylefield + value: scale, cycleMs, backgroundOpacity, staticColor, animation (OFF, SCROLL_L, SCROLL_R, PULSE, RAINBOW), template, gradient („A,B,C“), BooleansWert setzen
applyPresetvalue: Preset-Name (z. B. Sunset, Gold, Ocean)Gradient-Preset anwenden

  ]
}

3. Marketplace-Eintrag

Jeder Download-Link ist ein Eintrag in marketplace/marketplace.json. Einreichungen laufen per GitHub-Issue (Vorlage im Repo), der Maintainer trägt per Skript ein:

powershell -File scripts/Add-MarketplaceEntry.ps1 `
  -Id "mein-pack" -Name "Mein Pack" -Description "..." -Author "Du" `
  -Version "1.0.0" -DownloadUrl "https://github.com/.../mein-pack-1.0.0.zip" `
  -ModId "meine-mod" -JarHints "meine-mod" -CheckUrl -VerifyZip
powershell -File scripts/Test-MarketplaceJson.ps1 -CheckUrls -VerifyZips
FeldPflichtBedeutung
id, name, downloadUrljaID (a-z 0-9 . _ -), Anzeigename, direkter .zip-Link
modId, jarHintsjaKonflikterkennung: Fabric-ID + Dateinamen-Teile für den mods/*.jar-Scan (Loader-Check + Datei-Scan + Pack-gegen-Pack)
version, author, description, iconUrl, packType, installNotenein*Anzeige; *version empfohlen (Update-Vergleich)

4. Mod bauen & integrieren

Mod bauen

JDK 25, dann:
.\gradlew.bat build
# Output: build/libs/flexhud-*.jar
# Beispiel-Pack: powershell -File scripts/Build-ExamplePack.ps1

StepCount-Bridge

FlexHUD spricht StepCount per Reflection an (com.lokro.stepcount.StepCounter: start, stop, reset, toggleShow, shouldShowHud, isCounting, getSteps) – kein Hard-Dep, kein Crash ohne StepCount. Eigene Mods lassen sich analog anbinden (siehe StepcountBridge.java).

Sprache (DE/EN)

Alle UI-Strings laufen über client/i18n/Lang (Spiel-Sprache via options.languageCode, DE bei de*, sonst EN). Neue Strings immer in beiden Maps eintragen – nie hartcodieren.

Updates & Layout

Version kommt aus der Zip (.flexconfig > pack.json > Eintrag). Reinstalls sichern Positionen und spielen sie zurück; bei Strukturänderung warnt die Mod. Herkunft steht in marketplace/installed.json.
